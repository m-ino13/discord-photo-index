# 設計メモ

最終更新: 2026-10-15

使い方は [README](../README.md) を参照。このファイルには、仕様、判断の理由、API上の制約、つまずいた点を残す。

## 背景と目的

Discordサーバーで共有された写真をリスト化するためのプログラム。投稿が流れてしまうと見返しにくいので、写真が添付された投稿へのリンクを時系列の一覧にして、別チャンネルに置く。

Pythonが実行できる環境上で、一回きり実行するスクリプトとして作った。

## 仕様

1. 検索機能で、画像がN枚以上(既定5枚)含まれる投稿を集める。
2. 投稿先チャンネルごとに分け、チャンネルごとに投稿日時順に並べる。
3. 並べた投稿を順に見て、連投を除外する。直前に「残した」投稿と比べて、次のどちらかなら、日時が遅い方を除外する。
   - 投稿日が同じ(JST基準)
   - 投稿日時の差が3時間以下
4. チャンネルごとのリストをまとめ、全体を古い順に並べる。
5. 指定チャンネル(IDで指定)に、「日付(YYYY-MM-DD)・リンク・チャンネル名」を1行1件で投稿する。

枚数(`MIN_IMAGES`)と時間差(`GAP_HOURS`)は、`.env.custom` とコマンドライン引数で変更できる(引数が優先)。

## 設計判断

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 収集方法 | Search Guild Messages(`has=image`) | Botから使える検索APIが2026年3月に公式化された。全チャンネルの履歴を走査するより速い |
| 画像の数え方 | 添付ファイルのうち `image/*` のみ | 動画やURL埋め込みは「写真」とみなさない。`content_type` が無い添付は拡張子で判定 |
| 連投の判定 | 直前に「残した」投稿との比較 | 重複の削減より、拾い漏れを防ぐことを優先した(下記の例) |
| 「同じ日」の基準 | JST(`TIMEZONE`で変更可) | メンバーの生活時間に合わせる。DiscordのタイムスタンプはUTC |
| 対象範囲 | サーバー全体(Botが見えるチャンネルすべて) | スレッド内の投稿も含め、スレッド名で表示する |
| 出力 | 1行1件、1900文字ごとに分割、リンクのプレビューは抑制 | 投稿の文字数上限(2000)に収める |
| 再実行 | 追記する(前回分は消さない) | 削除権限や、投稿の追跡が不要になる |
| 実行方式 | ワンショットのスクリプト(スラッシュコマンドにしない) | 一回きりの処理で、既存Botの「投稿を検知して動く」構成に手を入れずに済む |
| 接続 | REST APIのみ(ゲートウェイには接続しない) | 既存Botと同じトークンで同時に動かしても干渉しない |
| 設定の持ち方 | トークンは `.env`(Git管理しない)、それ以外は `.env.custom`(Git管理する)。環境変数は使わず、2つのファイルから直接読む | 秘密情報とそれ以外を分け、設定をコードと一緒にバージョン管理できる。実行するシェルの環境に左右されない |

### 連投の判定の例

22:00、翌0:30、翌3:00、翌5:00 の順に、同じチャンネルへ写真が投稿された場合。

- 直前に「残した」投稿と比べる(採用): 22:00 と 3:00 が残る。0:30 は22:00の2.5時間後、5:00 は3:00の2時間後なので除外される。
- 直前の「元の」投稿と比べる(不採用): 22:00 だけが残る。連投が途切れない限り、1件にまとまってしまう。

## Discord APIの制約と対応

| 制約 | 対応 |
|---|---|
| 1回の取得は最大25件 | 25件ずつ取得して、ページングする |
| `offset` の上限は9975 | 上限を超えたら、取得済みの最古のIDを `max_id` にして、検索範囲をずらして続ける |
| 返却件数が `limit` より少ないことがある | 件数ではなく `offset` で進め、`total_results` に達したら終了する |
| 検索インデックスが未準備だと202が返る | `retry_after` の秒数(最低1秒)だけ待って、再試行する |
| 過去ログの再インデックス中は、結果が不完全な可能性がある | レスポンスの `doing_deep_historical_index` を見て、警告を表示する |
| `messages` は「メッセージ配列の配列」 | 平坦化して処理する |

## 経緯: `403 (50001 Missing Access)` と権限

最初の実行で、検索APIが `403 (code 50001 Missing Access)` になった。原因は、Botのロールで「メッセージ履歴を読む」がオフだったこと。

つまずきやすい点は次のとおり。

- 履歴取得のAPIは、この権限がなくてもエラーにならず、**0件を返す**。「エラーが出ない」ことは、権限がある証拠にならない。
- 既存Botは、投稿の通知を受け取るだけなので、「チャンネルを見る」だけで動いていた。
- 一部のチャンネルは、サーバー管理者の意図でBotに見せていない。それらは検索の対象外になる。

サーバー管理者に、ロールの「メッセージ履歴を読む」をオンにしてもらって解決した。権限の確認には、「各チャンネルの履歴取得が1件以上返るか」と「検索がエラーなく通るか」を見るとよい。この確認は `tools/diag_search.py` で行える(使い方は [README](../README.md) を参照)。
