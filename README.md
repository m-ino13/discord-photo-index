# discord-photo-index

Discordサーバーで共有された写真を見返しやすくするため、「画像が多数添付された投稿」へのリンクを時系列の一覧にして、指定チャンネルに投稿するスクリプト。

## 何をするか

1. サーバー内の投稿を検索し、画像がN枚以上(既定: 5枚)添付された投稿を集める
2. チャンネルごとに投稿日時順に並べ、連投された写真は最初の1件だけ残す
3. 全チャンネル分をまとめて古い順に並べ、指定チャンネルに投稿する

投稿は1行1件で、次の形式。

```
2026-09-01 https://discord.com/channels/<サーバーID>/<チャンネルID>/<メッセージID> #チャンネル名
```

仕様の詳細と、判断の理由は [docs/design.md](docs/design.md) を参照。

## リポジトリの構成

| ファイル | 内容 |
|---|---|
| `discord_photo_index.py` | 本体 |
| `tools/diag_search.py` | 検索が動かないときの原因切り分け用スクリプト |
| `.env` | Botのトークン(**Git管理しない**) |
| `.env.example` | `.env` の雛形 |
| `.env.custom` | サーバーID・出力先チャンネルIDなどの設定(Git管理する) |
| `docs/design.md` | 設計メモ |

## 動作環境

- Python 3.10(動作確認済み)
- discord.py 2.7.0、python-dotenv
- サーバーに参加済みのDiscord Bot

## 準備

```bash
pip install -r requirements.txt
cp .env.example .env     # DISCORD_TOKEN にBotのトークンを記入する
```

設定は環境変数ではなく、リポジトリ直下の2つのファイルから直接読み込む。

- `.env`: `DISCORD_TOKEN`(Botのトークン)だけを書く。`.gitignore` 済み。
- `.env.custom`: それ以外の設定を書く。

`.env.custom` の項目:

| 項目 | 必須 | 意味 |
|---|---|---|
| `GUILD_ID` | 必須 | 検索対象サーバーのID |
| `OUTPUT_CHANNEL_ID` | 必須 | 一覧の投稿先チャンネルのID |
| `MIN_IMAGES` | 任意(5) | 画像N枚以上を対象にする |
| `GAP_HOURS` | 任意(3) | 連投とみなす時間差(時間) |
| `TIMEZONE` | 任意(Asia/Tokyo) | 「同じ日」の判定と、表示する日付のタイムゾーン |

サーバーIDやチャンネルIDは秘密情報ではないが、リポジトリを公開する場合は、実際のIDを書いてコミットする前に扱いを決めること。

## 実行

```bash
python3 discord_photo_index.py --dry-run    # 投稿せず、結果を標準出力に表示
python3 discord_photo_index.py              # 実際に投稿
```

- `--min-images N` と `--gap-hours H` で、`.env.custom` の値を一時的に上書きできる。
- 所要時間の目安は、20,000件規模のサーバーで20〜30分(推定)。進捗はターミナルの同じ行に表示される。

## Botに必要な権限

- **チャンネルを見る**: 対象のチャンネルすべて。
- **メッセージ履歴を読む**: 検索に必須。オフだと検索が `403 (code 50001 Missing Access)` で失敗する。
- **メッセージを送信**: 出力先チャンネル。
- Developer Portal で **Message Content Intent** を有効にしておく(検索APIは、このインテントの有無で制限が変わる)。

Botに見せていないチャンネルは、検索の対象外になる。

## 検索が動かないとき

```bash
python3 tools/diag_search.py              # .env.custom の GUILD_ID を使う
python3 tools/diag_search.py <GUILD_ID>   # 別のサーバーIDを指定する
```

出力は、次の6つの手順に分かれる(`[1]`〜`[6]`の連番で表示される)。上から順に見て、最初にNGになったところが原因の手がかり。

| 手順 | 確認すること | NGのときの見方 |
|---|---|---|
| 1. ログイン | トークンが有効か | `.env` の `DISCORD_TOKEN` を確認する |
| 2. Botの参加サーバー | 対象のサーバーに参加しているか | 「対象のGUILD_ID」が表示されなければ、IDが違うか、未参加 |
| 3. チャンネル一覧 | サーバー情報を取得できるか | ※Botが見えないチャンネルも含めて返るので、権限の確認にはならない |
| 4. Botのロール権限 | サーバー全体のロール権限 | 「メッセージ履歴を読む」がFalseなら、サーバー管理者に依頼する |
| 5. チャンネルごとの履歴読み取り | 各チャンネルで履歴が実際に読めるか | 実効権限が「履歴=False」なら、そのチャンネルで権限が足りない。「0件返却」は、権限不足か、本当に投稿が無いかのどちらか |
| 6. 検索API | 検索がエラーなく通るか | 手順4・5が通っているのにNGなら、検索API固有の制限を疑う |

## 注意

- 再実行すると、同じ内容が追記で投稿される(前回の投稿は消さない)。
- サーバーが過去ログを再インデックス中は、古い投稿に取りこぼしが出る可能性がある。その場合は警告が表示されるので、時間をおいて再実行する。
